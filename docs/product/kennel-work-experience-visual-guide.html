The final Work experience

One desired result.
Many capable agents.
One inspectable truth.

Waldo Kennel turns a natural-language intention into a correctable Outcome contract, an authorized adaptive Mission, visible agent execution, and evidence-backed acceptance—without making the user coordinate provider sessions by hand.

The product is organized around what should become true.

Codex, DeepSeek, Claude Code, and future harnesses are replaceable executors underneath the Outcome. Kennel keeps the result, authority, evidence, and lineage coherent.

The product shift

From transcript supervision to Outcome supervision.

The user should not need to prompt-engineer, keep one coordinator context alive, or infer completion from terminals. Kennel carries the administrative and coordination burden while the user keeps authorship and authority.

Before
“Start an agent, explain the task, watch the transcript, and decide whether it probably worked.”
With Waldo Kennel
“State what should become true, correct Waldo’s understanding, approve the Mission, and supervise evidence-backed progress.”

The shared ontology

The durable result sits above every agent session.

This lineage is the backbone of the Work product. Each layer answers a different question and remains recoverable when providers restart, fail, or are replaced.

01Project

The repository or workspace, its policy, defaults, conversation, and shared context.

02Outcome

The durable result the user wants to make true. This is what Board/List displays.

03Contract revision

Desired state, criteria, evidence expectations, constraints, review, and authority ceiling.

04Plan revision / Mission

The reviewable topology: Work Units, dependencies, providers, permissions, cost, and recovery.

05Work Unit

One bounded responsibility with a clear objective and evidence obligation.

06Attempt

One execution try for that Work Unit, with a worktree and authority fence.

07AgentSessionRef

The provider-native Codex, DeepSeek, Claude Code, or future session attached to the Attempt.

08Evidence & Verification

Criterion-bound proof plus the declared independence of the check.

09Acceptance or Reopen

The user closes, requests rework, revises, reopens, or creates a successor Outcome.

Naming rule

There is no “Outcome session.”

An Outcome is responsibility truth. A session is temporary execution machinery underneath it.

One Outcomemay have no session yet, one direct session, several concurrent sessions, or replacement sessions.
One provider sessionbelongs to one Attempt and cannot accept the Outcome.
One Waldo identitypersists across bounded provider turns without pretending one LLM context lives forever.

Adaptive orchestration

The Mission graph changes because the Outcome changes.

Kennel proposes the smallest sufficient topology. A small Outcome should not inherit ceremony meant for a complex parallel Mission. The Project default provider is preferred—not blindly forced.

Authority, recovery, and proof

Agents receive autonomy inside an exact, reviewable envelope.

The daemon coordinates what may happen. Providers decide local tactics within the authorized RunBrief. The user remains the authority for material change and acceptance.

The clarifications we finalized

Common questions, one shared answer.

These answers resolve the ambiguities that otherwise lead design and engineering toward different products.

Is the Outcome the running agent session?
No. The Outcome is the durable desired result. It contains Contract and Plan revisions, Work Units, Attempts, sessions, Evidence, Verification, and Acceptance. Board/List shows Outcomes; Sessions is a separate operational projection.
Where does normal user input go when an agent needs help?
It attaches to an Outcome-level Decision Request. Kennel records one canonical answer and routes it to every affected Work Unit/session. Direct provider instruction is an explicit advanced action in Session Inspector.
Is Project Waldo one coordinator session that must stay open?
No. The Kennel daemon is the always-running coordinator. Project Waldo is a durable conversation projection composed from bounded provider turns. When a context becomes stale or too large, Kennel can safely continue it into a replacement session and retain a receipt.
When does automatic session replacement happen?
Only at a safe checkpoint when identity is lost/unhealthy, trusted context reserve is low, conservative adapter thresholds are reached, material grounding changed, independence requires a fresh verifier, or source revocation invalidates context. Purely mechanical same-provider continuation can happen with a receipt; material changes require user review.
Does every Outcome require multiple agents?
No. Small and medium Outcomes usually prefer the Project default harness and the smallest sufficient graph. One harness may fill several roles through separate sessions. Multi-provider Missions appear only when complexity, installed capabilities, and explicit authorization justify them.
Can DeepSeek be the Project default?
Yes, after `dsh` is installed, the user selects a valid profile, readiness succeeds, and prompt delivery is verified. DeepSeek is currently admitted as a worker. Coordinator/verifier eligibility remains capability-gated. Kennel never silently falls back after the user explicitly selects DeepSeek.
How do agents communicate without sharing one giant transcript?
Each Work Unit receives a purpose-built RunBrief. Dependencies pass durable, attributed handoff packets, artifacts, decisions, Evidence candidates, verification results, and recovery receipts. Provider transcripts remain operational detail, not the only shared memory.
What happens when an agent says it is done?
Its output becomes an observation or Evidence candidate. Kennel maps Evidence to the Contract criteria and runs the declared Verification method. Only the user Accepts; incomplete feedback keeps the Outcome open and may create a new Attempt or revised Plan/Contract.
How does Home relate to Work?
Home remains a separate personal responsibility surface. A future explicit ResponsibilityLink can connect a Home Open Loop to a Work Outcome without merging their contracts or silently moving personal context into a Project.

What the team should design and build

Operational clarity first. Expressiveness only when it teaches.

The Work surface should feel calm, dense, and trustworthy. It can be visually distinctive without making every lifecycle fact a card or every provider action a spectacle.

One reading path per state

The current decision or next safe action precedes telemetry, transcripts, or agent detail.

Responsibility before machinery

Outcome title and desired result dominate provider/model labels.

Truth before optimism

Starting, unconfirmed, blocked, recovering, verified, and accepted remain distinct.

Context is always visible

Project, Outcome, Work Unit, Attempt, and inspected session never blur together.

Graph plus accessible list

The Mission graph explains topology; the list preserves scanability and keyboard access.

Motion earns its place

Use it for spatial transitions and binding receipts, not endless AI-thinking decoration.

Failures keep their lineage

Replacement Attempts and sessions are visible; errors are never erased by a retry.

Provider honesty

Unsupported controls are absent or explained. There is no silent provider fallback.

Restart is part of the flow

Return users to the exact canonical state, selection, and next safe action.

The alignment sentence

Waldo Kennel lets a user supervise the truth of an Outcome while Kennel coordinates the temporary agent sessions required to make it real.
